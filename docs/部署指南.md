# 自用版 MT4/MT5 跟单系统 · 部署指南

> 适用范围：只跟自己的账户，不对外服务。
> 链路延迟约 0.5~1 秒（MQL 定时器最小 1 秒），适合波段、日内，不适合超短线剥头皮。

## 一、架构

```
Master 终端（Sender EA） --HTTP POST JSON--> 中转服务（Python FastAPI，127.0.0.1:8787）
                                                        |
Follower 终端（Receiver EA） <--HTTP 轮询 GET------------
```

- 所有组件跑在**同一台 Windows VPS** 上，localhost 通信，延迟最低。
- 中转服务只监听 127.0.0.1，不对外暴露，无需鉴权。
- 事件按 `master_id` 分流，内存保留最近 5000 条，`seq` 全局自增；Receiver 用 `since` 增量拉取，天然去重；`last_seq` 存在 EA 本地文件，重启后续传。

## 二、VPS 环境准备

1. 开一台 **Windows** VPS（Windows Server 2019 / 2022 均可），建议 2 核 4G 起步。
   每个 MT 终端约占用 150~300MB 内存，按"1 个 master + N 个 follower"估算。
2. VPS 地理位置尽量靠近券商服务器（比如券商服务器在香港就选香港 VPS），降低订单执行延迟。
3. 安装 Python 3.10+（官网 python.org，安装时勾选 **Add python.exe to PATH**）。

## 三、安装 MT4 / MT5（可多开）

1. 从**券商官网**下载 MT4 / MT5 安装包（不要用第三方修改版）。
2. 多开方法：安装第一个后，把安装目录整个复制一份（如 `C:\MT4-Master`、`C:\MT4-Follower1`），
   每个目录单独运行 `terminal.exe`，分别登录 master / follower 账号。
   建议给快捷方式改名区分，避免登错账号。
3. 每个终端都要保持 24 小时在线：VPS 不要休眠（电源计划设为"高性能"，关闭睡眠）。

## 四、部署中转服务

```bat
cd C:\mt-copy\relay
python -m venv venv
venv\Scripts\pip install -r requirements.txt
```

启动测试：

```bat
start.bat
```

浏览器打开 http://127.0.0.1:8787/health，看到 `{"ok":true,...}` 即正常。

### 开机自启（二选一）

**方案 B：Windows 计划任务**

1. 打开"任务计划程序" → 创建任务（不是基本任务）。
2. 触发器：系统启动时。
3. 操作：启动程序 `C:\mt-copy\relay\start.bat`。
4. 勾选"不管用户是否登录都要运行"。

## 五、安装 EA

EA 已合并为跨平台统一版（同一份源码，`#ifdef __MQL5__` 做双平台兼容）：

| 文件 | 放到 | 挂到 |
|---|---|---|
| `Sender.mq4` | Master 终端 `MQL4/Experts/`（MT4）或 `MQL5/Experts/`（MT5） | Master 账号的任意图表 |
| `Receiver.mq4` | Follower 终端 `MQL4/Experts/`（MT4）或 `MQL5/Experts/`（MT5） | Follower 账号的任意图表 |

> **MT5 上使用时**：把 `Sender.mq4` / `Receiver.mq4` 复制一份，改扩展名为 `.mq5` 即可，
> 代码内已用 `#ifdef __MQL5__` 做了双平台兼容（MT5 走 `OnTradeTransaction` 实时分支 + `CTrade` 下单，
> MT4 走 `OnTimer` 轮询分支 + `OrderSend` 系列函数）。

步骤：

1. MT4 按 `F4` 打开 MetaEditor，把 `.mq4` 文件拷入 `MQL4/Experts/`，点"编译"，0 错误 0 警告。
   MT5 同理（改名后的 `.mq5` → `MQL5/Experts/`）。
2. **关键设置**：MT 终端 → 工具 → 选项 → EA交易：
   - 勾选"允许算法交易"；
   - 勾选"**允许 WebRequest** 用于列出的 URL"；
   - 点"添加"，填入 `http://127.0.0.1:8787`（必须和 EA 参数里的地址一致）。
   
   > 漏掉这一步 EA 会报 4060 错误，事件发不出去。
3. 把编译好的 EA 从"导航器"拖到任意图表，**先勾选"允许算法交易"**，再配置参数。

## 六、EA 参数配置

### Sender（Master 端）

| 参数 | 说明 |
|---|---|
| `InpMasterId` | Master 标识，如 `master1`（Receiver 端填同一个；只能用字母数字） |
| `InpRelayUrl` | `http://127.0.0.1:8787` |
| `InpTimeoutMs` | HTTP 超时毫秒，默认 5000 |
| `InpMagicFilter` | 只推送该 Magic 的订单，`-1`=全部 |

注意：Sender 启动时会静默采集一次当前持仓快照，**启动前已有的持仓不会被推送**。
正确顺序：先挂 EA，再开始交易。

### Receiver（Follower 端）

| 参数 | 说明 |
|---|---|
| `InpMasterId` | 与 Sender 一致 |
| `InpRelayUrl` | `http://127.0.0.1:8787` |
| `InpLotMode` | `0`=按倍数跟随，`1`=固定手数 |
| `InpLotMultiplier` | 按倍数时的倍数，如 `0.5` |
| `InpFixedLots` | 固定手数模式的手数 |
| `InpSymbolMap` | 品种映射，如 `EURUSD=EURUSD,GBPUSD=GBPUSD.pro`（空=同名） |
| `InpSymbolFilter` | 只跟随这些品种，逗号分隔（空=全部） |
| `InpSlippage` | 滑点（点），默认 30 |
| `InpMagicNumber` | 跟单订单的 Magic，默认 20261011（用于区分手工单） |
| `InpFloatMode` | 浮亏跟单模式：`0`=关闭（默认，所有信号订单都跟）；`1`=按浮亏金额；`2`=按订单序号 |
| `InpFloatAmount` | 模式1 阈值：信号浮亏达到该金额（账户货币，取绝对值比较）才开始跟单，默认 100.0 |
| `InpFloatOrderNum` | 模式2 阈值：信号开到第几单才开始跟单，默认 3 |

### 浮亏跟单（Receiver 端，对标 OKCOPY）

**两种模式**（`InpFloatMode`）：
- **模式1 按浮亏金额**：master 账户浮动盈亏 ≤ `-InpFloatAmount` 时触发。例如阈值 100，master 浮亏到 -100（账户货币）就开始跟。
- **模式2 按订单序号**：master 当前持仓订单数 ≥ `InpFloatOrderNum` 时触发。例如设为 3，master 开到第 3 单就开始跟。适合马丁策略（越跌越加仓，浮亏大了才值得跟）。

**门行为**（关键）：
1. 门没开之前，master 的所有新开仓**全部跳过**，日志打印"浮亏跟单未触发"。
2. 门打开后，**只跟门打开之后的新开仓**，门开之前已有的持仓**不补**。
3. master 持仓清零 **且** 本地镜像持仓也平完 → 门重新关闭（重新武装），等待下次触发。
4. 门状态（开/关）保存在 `mtcopy_<masterid>.dat` 里（格式 `"seq,gate"`），EA 重启不丢失；老版本只有 seq 的文件也能兼容读取。

**数据来源**：Sender 每 5 秒推送一条 `snapshot` 事件（浮动盈亏/持仓数/余额/净值），Receiver 收到后评估门。注意 MQL4 的持仓数包含挂单。

**适用场景**：跟马丁/网格类信号——平时不跟，等信号浮亏拉大（加仓到第 N 单）再介入，成本更优。

## 七、模拟盘测试检查清单（必须做）

> **周末休市也能先测链路**：启动中转服务 → 在 Follower 图表挂好 Receiver EA →
> 双击 `relay/test-inject.bat`，它会依次注入模拟开仓 / 改单 / 平仓事件（后两步还注入模拟账户快照，验证浮亏跟单门）；
> 去 MT 终端「专家」日志里看 Receiver 有没有正确收到、解析、映射手数并发单。
> 休市拒单是正常的，关键看日志证明"发射→中转→接收→映射"全链路通。
> 开盘后再按下面清单用 0.01 手模拟盘做真实跟单验证。

1. 两个终端都先登录**模拟盘**账号。
2. 中转服务 `/health` 返回正常；EA 左上角显示笑脸（算法交易已启用）。
3. Master 开一笔小单 → Follower 应在约 1 秒内出现同向订单（注释为 `copy#<ticket>`）。
4. Master 修改 SL/TP → Follower 同步修改。
5. Master 平仓 → Follower 同步平仓。
6. Master 挂 buy limit → Follower 同步挂单；删除挂单 → Follower 同步删除。
7. 重启 Receiver EA → 应从上次 seq 继续，不重复开单（检查 `MQL4/Files/` 或 `MQL5/Files/` 下的 `mtcopy_<masterid>.dat`）。
8. 浮亏跟单测试（`InpFloatMode=1/2`）：**休市也能测**——把 Receiver 设为 `InpFloatMode=1、InpFloatAmount=100` 后运行 `relay/test-inject.bat` 的 `[5/6][6/6]` 步，它会注入模拟账户快照（浮亏 -150 → 触发开门 → 新开仓跟单 → 快照清零 → 门重置 → 新开仓跳过），对照日志看"浮亏跟单已触发 / 浮亏跟单重置 / 浮亏跟单未触发，跳过"三处打印。开盘后也建议让 master 真实开小仓再走一遍，确认行为一致；master 全部平仓且跟单平完后门重新关闭。
9. 切到**实盘前**，先用最小手数跑 1~2 天，确认行为符合预期。

## 八、故障排查

| 现象 | 排查 |
|---|---|
| EA 日志报 4060 | WebRequest 白名单没加：工具→选项→EA交易→添加 `http://127.0.0.1:8787` |
| EA 日志报 4061 / 超时 | 中转服务没启动；检查端口 8787 是否被占用 |
| Follower 不跟单 | `InpMasterId` 两端是否一致；品种映射是否正确（日志会打印"品种不可用"） |
| Follower 开仓失败 | 看日志 retcode：10016=价格/SLTP 无效，10027=服务器禁自动交易 |
| 重复开单 | 同一 master 事件被两个 Receiver 处理（一个 master_id 只挂一个 Receiver） |
| 中转服务内存事件丢失 | 服务重启会清空内存事件（保留 5000 条上限）；Receiver 的 seq 文件保证不重不漏 |

## 九、已知限制

1. **延迟约 0.5~1 秒**：MQL4/MQL5 的 `EventSetTimer` 最小 1 秒，Receiver 是轮询拉取；
   MT5 的 Sender 用 `OnTradeTransaction` 是毫秒级推送，但 follower 端仍是 1 秒轮询。
   不适合超短线剥头皮。
2. **MT5 建议用 Hedging（对冲）账户**：Netting（净头）账户下同品种多笔持仓会合并成一笔，
   master 加仓/部分平仓时映射会失真。
3. **挂单触发**：master 挂单成交时，Sender 先推 close（删挂单）再推 open（新持仓），
   Receiver 侧是"删 follower 挂单 + 开 follower 新单"，中间有约 1 秒空档。
4. **反手单**（INOUT）：按"先平后开"两条事件处理。
5. **JSON 解析限制**：事件 comment 里不要出现大括号 `{}`（极简解析器的限制）。
6. **止损止盈距离**：follower 券商的止损距离限制（STOPLEVEL）可能与 master 不同，
   太近的 SL/TP 会被拒单，日志会打印错误码，请按 follower 券商规则调整。
7. **只跟自己的账户**：本系统无任何鉴权和多租户设计，不要暴露到公网，不要给别人用。
